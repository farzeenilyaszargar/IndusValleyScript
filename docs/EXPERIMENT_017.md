# Experiment 017: constrained substitution keys and known-cipher calibration

17 October 2026. Design recorded before preparing new inputs, optimizing keys or evaluating results. Selected substitution/noisy-channel passages of Knight et al. (2006, ACL P06-2065) and cognate-correspondence assumptions of Luo et al. (2019, ACL P19-1303) were inspected. Our method is a simpler bijective bigram search, not replication of EM, neural minimum-cost flow, cognate translation or an identified Indus sound system.

Use the pinned Tamil/Vedic source files and existing letter-plus-marks normalization. Partition complete normalized source documents (canonical exact/reverse copies together, seed314) into 60% language-model groups and 40% calibration groups. No calibration document trains the target model. Source documents are verses or Vedic sentence blocks, not necessarily independent books or chronological strata. Take the 32 most frequent units from language-model documents, map all other units to a fixed UNK, and retain Unicode labels for these selected writing units. They are not asserted to be Indus-equivalent phonemes, aksharas or reconstructed ancient speech.

Fit add-0.5 unigrams and strength20 interpolated bigrams on full model documents, with no cross-document edges. Score a mapped short string by its initial-unit unigram plus internal bigrams, without EOS. Preserve every unknown slot; never delete tokens or create edges across missing units. Freeze numeric counts and selected single-unit labels in attributed offline input artifacts.

First generate a known artificial permutation cipher of 2,156 calibration windows with exactly the original Indus length list (seed17), using only held source documents. Split exact/reversed ciphertext copies together using seed42. Cipher train/validation/test windows can overlap within their held source documents; disclose that limitation. Evaluate recovery against the secret key, never supplied to search or validation selection. Report true-key loss as an oracle diagnostic, key accuracy and token-weighted recovery. This does not establish historical model suitability.

Then test ICIT complete unique texts and our fictional administrative-control seed17 records. Split each at full original IDs before selecting its top32 training signs. Rare/unseen signs become a fixed UNK slot; report token coverage and collapsed-pattern overlap. Use the same bijective 32-to-32 key space and budget in all conditions. One sign/one selected writing unit is a deliberately narrow assumption, not a supported property of the full script.

For each language and each input condition: frequency-rank baseline; 20 seeded random bijections; five optimization starts (frequency rank plus random seeds17/29/43/59). Each start makes 20,000 swap proposals with geometric temperature20→0.05 total bits, followed by at most two greedy all-pair swap sweeps. Round proposal deltas to 1e-8 bits for portable tie handling. Keep each start's best training key, select a start by validation loss only, and evaluate test once. Export every start's key/loss, random baseline scores, selected conditional recodings of the first20 test strings and pairwise key agreement. All candidate Unicode recodings are explicitly hypothetical and incomplete, never translations.

Target-unit coverage and genres differ between proxies, so absolute cross-language loss cannot select a family. Any likelihood gain on the non-phonetic control is a specificity warning. Synthetic key recovery diagnoses this solver under this artificial channel; real Indus key correctness remains unobservable without external anchors. Preserve source license/attribution, benchmark inventories and all negative cases. No optimized key is adopted as a deciphered phonetic value.
